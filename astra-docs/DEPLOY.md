# Deploying `docs.astra.dev`

This site is deployed on [Mintlify](https://mintlify.com/) (free OSS tier). The deployment is automated via the GitHub App — Mintlify pulls from `main` and rebuilds on every push.

## Connect the repo

1. Sign in at [`dashboard.mintlify.com`](https://dashboard.mintlify.com/) with the GitHub account that owns `astra-dev/astra`.
2. Install the Mintlify GitHub App on the `astra-dev/astra` repo.
3. In the Mintlify dashboard, set the **docs subdirectory** to `astra-docs`.
4. Push to `main` — the first build runs automatically.

Default URL: `astra.mintlify.app`. The custom domain step below switches it to `docs.astra.dev`.

## Custom domain

### 1. Add the DNS record

At the DNS provider for `astra.dev`, add:

```
Type:   CNAME
Name:   docs
Value:  cname.mintlify.app
TTL:    300
```

The exact `Value` may differ — confirm it in **Mintlify dashboard → Settings → Custom Domain**.

Verify the DNS record is live:

```bash
dig docs.astra.dev CNAME
```

### 2. Add the domain in Mintlify

1. **Mintlify dashboard → Settings → Custom Domain**.
2. Enter `docs.astra.dev`.
3. Wait for SSL provisioning (Let's Encrypt via Mintlify). Typically under 30 minutes; sometimes a few hours.

Verify HTTPS:

```bash
curl -I https://docs.astra.dev
```

## Post-deploy checks

After the first successful deploy, smoke-test these URLs:

- `https://docs.astra.dev/` — redirects to `/introduction`.
- `https://docs.astra.dev/llms.txt` and `https://docs.astra.dev/llms-full.txt` — Mintlify auto-generates these for AI ingestion. If absent, the CI job at [`.github/workflows/reference.yml`](.github/workflows/reference.yml) generates `llms-full.txt` manually via [`scripts/build-llms-txt.py`](./scripts/build-llms-txt.py).
- `https://docs.astra.dev/sitemap.xml` — sitemap auto-generated by Mintlify.
- Search bar: query a known page title (e.g. "AstraServer") and confirm the result lands on `/runtime/astra-server`.

## Analytics

`mint.json` already wires Plausible:

```json
"analytics": {
  "plausible": {
    "domain": "docs.astra.dev"
  }
}
```

Create the Plausible site at [`plausible.io`](https://plausible.io/) with the domain `docs.astra.dev`. Mintlify will inject the tracking snippet automatically.

Mintlify's built-in analytics is independently available in the dashboard — keep both enabled (Plausible for owner-visible metrics, Mintlify for content-team metrics).

## Versioning

To cut a new docs version when Astra ships `v0.2`:

1. Update `mint.json` → `versions: ["v0.1", "v0.2"]`.
2. Copy current content into `astra-docs/versions/v0.1/`.
3. Update [`.github/workflows/reference.yml`](.github/workflows/reference.yml) to write to the active version's reference dir.
4. Smoke-test the version switcher in Mintlify's preview environment.

See [`contributing.mdx`](./contributing.mdx#releasing-a-new-docs-version) for the contributor-facing version-cut workflow.

## OG images

Each top-level section has a 1200×630 OG image under `astra-docs/images/og/`:

- `default.png` — fallback for pages without a section override.
- `concepts.png`, `compiler.png`, `runtime.png`, `observability.png`, `reference.png`, `cookbook.png`, `comparisons.png` — per-section.

To regenerate (optional, when rebranding):

```bash
python scripts/build-og.py  # Pillow-based template renderer (not yet shipped)
```

## Local dev

```bash
cd astra-docs
npx mintlify@latest dev
```

Default port: `http://localhost:3000`.

Validation:

```bash
mintlify validate            # mint.json schema check
mintlify broken-links        # internal link audit
python scripts/check-frontmatter.py
python scripts/audit-codegroups.py --fail-on-missing
```

All four pass cleanly on `main`.
