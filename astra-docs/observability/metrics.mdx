`compute_metrics()` produces a `MetricsSnapshot` by scanning the trace and span store over a recent time window. It is intentionally pull-based: there is no parallel metrics pipeline, and counters live nowhere except the trace tree. The function caps the scan at `max_traces` (default 500) so dashboards stay responsive even when traffic is high; beyond that ceiling, switch to a dedicated metrics store.

Source: [query/metrics.py](https://github.com/astra-dev/astra/blob/main/astra/observability/src/observability/query/metrics.py).

## Full field reference

### Window

| Field | Type | Meaning |
| --- | --- | --- |
| `window_start` | datetime | Inclusive lower bound. Defaults to `now - hours`. |
| `window_end` | datetime | `now` at call time, UTC. |
| `trace_sample_size` | int | Traces actually scanned. May be less than the true count if capped. |
| `truncated` | bool | `True` when the `max_traces` ceiling was hit before reaching `window_start`. |

### Request counts and rates

| Field | Type | Meaning |
| --- | --- | --- |
| `request_count` | int | Total scanned. |
| `success_count` | int | `status == SUCCESS`. |
| `error_count` | int | `status == ERROR`. |
| `running_count` | int | In-flight at scan time. |
| `success_rate` | float | `success_count / (success_count + error_count)`, in `[0, 1]`. Zero when no traces completed. |
| `error_rate` | float | `error_count / (success_count + error_count)`. |

Running traces are not counted toward success or error rates.

### Latency

| Field | Type | Meaning |
| --- | --- | --- |
| `latency_p50_ms` | float \| None | Median end-to-end trace duration over completed traces. |
| `latency_p95_ms` | float \| None | 95th percentile. |
| `latency_p99_ms` | float \| None | 99th percentile. |
| `latency_avg_ms` | float \| None | Arithmetic mean. |

All four become `None` when no completed traces exist in the window. Percentiles use linear interpolation between the two nearest ranks.

### Tokens

| Field | Type | Meaning |
| --- | --- | --- |
| `total_tokens` | int | Sum of `trace.total_tokens` across the window. |
| `input_tokens` | int | Sum of `trace.input_tokens`. |
| `output_tokens` | int | Sum of `trace.output_tokens`. |
| `thoughts_tokens` | int | Hidden-reasoning tokens, summed. |
| `avg_tokens_per_request` | float | `total_tokens / request_count`. Zero when no traces. |

### Streaming

| Field | Type | Meaning |
| --- | --- | --- |
| `avg_ttft_ms` | float \| None | Mean of `ttft_ms` over all `GENERATION` spans that recorded it. |
| `generation_p50_ms` | float \| None | Median duration of completed `GENERATION` spans. |
| `generation_p95_ms` | float \| None | 95th percentile of completed `GENERATION` spans. |

### Top-N

Each top-N field is a list of `{name, count, extra}`. Default `top_n` is 8.

| Field | What ranks | `extra` contents |
| --- | --- | --- |
| `top_models` | LLM model identifier from `trace.model` | `{"total_tokens": int}` |
| `top_tools` | Tool span name (`tool_name`, `tool_qualified_name`, or span name) | `{"error_count": int, "error_rate": float}` |
| `top_agents` | `agent_id` attribute on the trace | empty |
| `top_teams` | `team_id` attribute on the trace | empty |

### Tool reliability

| Field | Type | Meaning |
| --- | --- | --- |
| `tool_call_count` | int | Total `TOOL` spans observed. |
| `tool_error_count` | int | `TOOL` spans with `status == ERROR`. |
| `tool_error_rate` | float | `tool_error_count / tool_call_count`, zero when no tool calls. |

## REST shape

```bash
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8000/observability/metrics?hours=24&max_traces=500&include_system=false" \
  | jq
```

The response body is `MetricsSnapshot` plus the datetimes serialized as ISO 8601 strings. See [REST endpoints](/runtime/rest-endpoints) for the wrapper Pydantic model on the route handler.

## Python API

```python
from observability.query.metrics import compute_metrics

snap = await compute_metrics(
    engine.storage,
    hours=24,
    max_traces=500,
    include_system=False,
    top_n=8,
)

print(f"requests: {snap.request_count}")
print(f"success rate: {snap.success_rate:.1%}")
print(f"p95 latency: {snap.latency_p95_ms} ms")
print(f"avg TTFT: {snap.avg_ttft_ms} ms")
for item in snap.top_tools:
    print(f"  {item.name}: {item.count} calls, {item.extra['error_rate']:.1%} errors")
```

`since` may be passed explicitly (timezone-aware UTC datetime) and takes precedence over `hours`. Naive datetimes are coerced to UTC.

<Tip>
For a "last 5 minutes" widget on a busy server, drop `max_traces` to 100 to keep the scan tight. For a daily "yesterday" report, pump it to 5000 and accept a slower response.
</Tip>

<Warning>
The aggregator does an N+1 fetch for spans (one `get_spans_for_trace` per trace). This is acceptable because of the trace cap, but it is not safe to remove the cap without also batching span retrieval at the storage layer.
</Warning>

## Interpreting truncated snapshots

When `truncated=True`, you know two things: (a) the window is wider than the cap can cover, and (b) the snapshot represents the most recent `trace_sample_size` traces, not a random sample. Percentiles in that case are biased toward recent behaviour. If you alert on `latency_p95_ms`, also alert on `truncated` so you can distinguish "things are slow" from "we lost visibility".

## System traces

`include_system=False` is the default and filters out traces with names that start with `server.`. Set `True` to include them when debugging startup or sync issues.
